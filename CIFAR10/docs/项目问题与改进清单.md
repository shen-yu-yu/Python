# CIFAR-10 项目问题与改进清单

> 本文档记录本项目在开发、审查过程中暴露出的问题，供日后对照警醒。  
> 最后更新：2026-08-24

---

## 一、已修复的问题（曾经犯过的错）

这些问题已经在当前代码中修掉，但很容易在新项目里再犯一遍，值得记住。

### 1. 准确率分母算错

**错误写法：**

```python
accuracy = correct / (len(loader) * BATCH_SIZE)
```

**问题：** 最后一个 batch 往往不满 `BATCH_SIZE`（例如 CIFAR-10 测试集 10000 张、batch=128 时，最后一批只有 16 张），用 `len(loader) * BATCH_SIZE` 会高估分母，**准确率被低估**。

**正确写法：**

```python
accuracy = correct / len(loader.dataset)
```

---

### 2. `predict.py` 没有真正做预测

**错误：** 加载了模型，却只显示真实标签，从未调用 `model(...)`。

**正确流程：**

```python
x = images[0:1].to(config.DEVICE)   # 保留 batch 维 [1, 3, 32, 32]
with torch.no_grad():
    pred = model(x)
pred_idx = pred.argmax(1).item()    # .item() 转成 Python int
```

---

### 3. 输入维度少了 batch 维

**错误：**

```python
pred = model(images[0])  # shape: [3, 32, 32]，Conv2d 期望 [N, C, H, W]
```

**报错：** `Expected 4-dimensional input ... but got 3-dimensional input`

**正确：**

```python
x = images[0:1]           # 或 images[0].unsqueeze(0)
pred = model(x)
```

---

### 4. 用 tensor 当下标

**错误：**

```python
config.CLASSES[pred.argmax(1)]      # argmax 返回 tensor，不能直接索引
config.CLASSES[first_label]          # label 也是 tensor
```

**正确：**

```python
config.CLASSES[pred.argmax(1).item()]
config.CLASSES[labels[0].item()]
```

---

### 5. 加载权重缺少 `map_location`

**问题：** 在 GPU 上训练的 `model.pth`，在纯 CPU 环境加载可能直接报错。

**正确：**

```python
torch.load(path, weights_only=True, map_location=config.DEVICE)
model.load_state_dict(...)
model = model.to(config.DEVICE)
```

---

### 6. 保存 checkpoint 前未创建目录

**问题：** `torch.save(..., "checkpoints/model.pth")` 时，若 `checkpoints/` 不存在会失败。

**正确：**

```python
config.CHECKPOINT_RESULT.parent.mkdir(parents=True, exist_ok=True)
torch.save(model.state_dict(), config.CHECKPOINT_RESULT)
```

---

### 7. 只保存最后一个 epoch，评估却期望最优模型

**问题：** 训练 15 个 epoch 后，最后一个 epoch 不一定是验证集最好的；若测试/预测加载的是 `model.pth`（最后一轮），结果可能偏差。

**改进：** 训练时跟踪 `best_acc`，验证集创新高时保存 `best.pth`；测试和预测默认加载 `CHECKPOINT_BEST`。

---

### 8. 验证集 / 测试集不必要的 `shuffle=True`

**问题：** 评估阶段不需要打乱顺序；`predict.py` 用 `next(iter(test_loader))` 时，shuffle 会导致每次看到的图片不同。

**正确：** train 用 `shuffle=True`，val / test 用 `shuffle=False`。

---

### 9. 归一化参数多处硬编码

**问题：** `mean` / `std` 在 `data.py` 和 `predict.py` 各写一份，改一处容易漏另一处，反归一化显示会出错。

**改进：** 统一到 `src/config.py` 的 `MEAN`、`STD`，训练和可视化共用。

---

### 10. 脚本缺少 `if __name__ == "__main__"`

**问题：** 模块被 `import` 时会立刻执行训练/测试，不符合 Python 惯例。

**正确：**

```python
def main():
    ...

if __name__ == "__main__":
    main()
```

---

### 11. 命名拼写错误

| 错误 | 正确 |
|------|------|
| `NUM_EPOCHES` | `NUM_EPOCHS` |
| `get_transformers()` | `get_transforms()` |

函数名用复数 `transformers` 容易和 HuggingFace 的 Transformer 模型混淆。

---

### 12. 训练时加载了用不到的 test 集

**问题：** `get_dataloaders()` 一次返回 train/val/test，但 `train.py` 只需要前两个，白白下载和构建 test loader。

**改进：** 拆成 `get_train_val_loader()` 和 `get_test_loader()`，各取所需。

---

### 13. 文档与代码不一致

**问题：** README 写「测试加载 `model.pth`」，代码实际加载 `best.pth`，容易误导自己或他人。

**原则：** 改代码时同步改 README，尤其是 checkpoint 路径、默认行为、目录是否需要手动创建等。

---

### 14. 源码、脚本、产物混在根目录

**问题：** 配置文件、模型定义、训练脚本、下载数据、权重文件全堆在项目根目录，越改越乱。

**改进：** 采用轻量分层（见第六节），不急于上完整 ML 工程结构。

---

## 二、当前仍待改进的问题

以下问题不影响项目基本跑通，但值得在后续迭代中处理。

### 训练流程

| 问题 | 说明 |
|------|------|
| 无 train accuracy | 只记录 loss 和 val accuracy，难以判断过拟合 |
| 无学习率调度 | 固定 `lr=1e-3`，后期可能收敛变慢或震荡 |
| 无 early stopping | 固定 15 epoch，可能在 val 不再提升时仍继续训练 |
| 随机性控制不完整 | 仅数据划分固定 `seed=42`；模型初始化、DataLoader shuffle、CUDA 未统一设 seed，多次训练结果可能不同 |

### 健壮性

| 问题 | 说明 |
|------|------|
| 缺少异常处理 | OOM、数据集下载失败等会直接中断，无友好提示 |

### 模型与性能（入门项目可接受）

| 问题 | 说明 |
|------|------|
| 网络较浅、无 BatchNorm | 15 epoch 下精度上限一般，离 CIFAR-10 常见强基线（ResNet 等）有距离 |
| `NUM_WORKERS = 0` | Windows 上常见写法，但数据加载偏慢；Linux 上可适当增大 |

## 三、自查清单（新项目开写前过一遍）

写深度学习小项目时，可按下面顺序自检：

- [ ] 准确率 / loss 的分母是 **样本总数**，不是 `len(loader) * batch_size`
- [ ] 推理时输入是 **4 维** `[N, C, H, W]`，类别索引用 **`.item()`**
- [ ] 加载权重有 **`map_location`**，模型和数据在同一 **`DEVICE`**
- [ ] 保存前 **`mkdir(parents=True, exist_ok=True)`**
- [ ] 区分 **best checkpoint** 与 **last checkpoint**，测试/预测加载的是哪一个要想清楚
- [ ] val / test **不 shuffle**（除非有特殊需求）
- [ ] 超参数、均值方差、类别名等 **只定义一处**（通常放 `config.py`）
- [ ] 入口脚本有 **`if __name__ == "__main__"`**
- [ ] **README 与代码行为一致**
- [ ] 只加载 **当前脚本真正需要** 的数据集
- [ ] 需要复现结果时，对 **数据划分 + 模型初始化 + 训练过程** 统一设 seed
- [ ] **源码 / 入口脚本 / 运行产物 / 文档** 分目录存放

## 四、常见 PyTorch 报错速查

| 报错 / 现象 | 常见原因 |
|-------------|----------|
| `Expected 4-dimensional input` | 忘了 batch 维，用了 `images[0]` 而不是 `images[0:1]` |
| `indices must be integers` / 索引报错 | 用 tensor 当下标，缺 `.item()` |
| `FileNotFoundError: checkpoints/...` | 保存前未创建目录，或尚未训练 |
| CUDA tensor on CPU / 设备不一致 | 模型或输入未 `.to(DEVICE)` |
| 准确率「看起来偏低一点」 | 分母用了 `len(loader) * BATCH_SIZE` |
| 每次 predict 看到的图不一样 | test DataLoader 开了 `shuffle=True` |
| CPU 上无法加载 GPU 训练的权重 | 缺 `map_location=config.DEVICE` |

---

## 五、改进优先级建议

若时间有限，建议按此顺序处理：

1. **高优先级（影响正确性）** — 本文档「第一节」中的各类问题，新项目一律避免
2. **中优先级（影响体验）** — checkpoint 存在性检查、train accuracy 日志、README 同步
3. **低优先级（追求更好效果）** — LR scheduler、early stopping、更强模型结构、完整 reproducibility
